LEVEL 01 PROJECT TUTORIAL EXPANSION

Developer Portfolio

A complete Web Foundations capstone linking HTML, CSS, responsive layout, accessibility, Git/GitHub and deployment.

1. Project brief

Build a professional personal portfolio that explains who you are, what you can do, what you have built and how someone can contact you. The target is not visual novelty; it is clarity, credibility, responsiveness and clean implementation.

2. Two build modes

GUIDED BUILD

First attempt

Follow the milestone sequence, inspect examples and use the checklists.

INDEPENDENT CHALLENGE

Second attempt

Use only the brief, requirements and rubric. Rebuild without step-by-step instructions.

3. Minimum requirements

  • Semantic header/nav/main/footer
  • Hero with concise positioning statement
  • About section
  • Skills / capabilities
  • Education and/or experience
  • At least three project cards
  • Contact form UI with labels
  • Responsive layout
  • Keyboard-friendly navigation and visible focus
  • GitHub repository + meaningful history
  • README + live deployment

4. Suggested information architecture

Header: brand / nav
Hero: who you help + what you do + CTA
About: short professional narrative
Capabilities: grouped skills
Projects: evidence
Experience / education
Contact
Footer

5. Build milestones

Content first

Write real copy before designing. Placeholder text hides information problems.

Semantic HTML

Build the complete document with no layout CSS.

Base design system

Define color, type, spacing and component tokens.

Responsive layout

Implement nav, hero and project grid using Flexbox/Grid.

Accessibility pass

Keyboard, focus, alt text, labels, heading hierarchy and contrast.

Git + deploy

Push, publish, test the public URL and document the project.

6. README template

# Developer Portfolio ## Live site https://... ## Purpose One paragraph explaining the goal. ## Features - Responsive layout - Semantic HTML - Accessible contact form UI ## Built with HTML, CSS, Git, GitHub Pages ## What I learned 3–5 concise bullets. ## Next improvements 2–3 realistic improvements.

7. Review checklist

Content

Specific, concise and evidence-based.

Responsive

No overflow; text remains readable.

Accessibility

Keyboard path, focus, labels and alt text checked.

Technical

Valid paths, clean repository, no secrets.

8. Self-review rubric

AreaTarget
HTMLSemantic, logical headings, form labels, meaningful links
CSSReusable classes, consistent spacing, responsive layout
Git6+ meaningful commits and clear branch history if used
AccessibilityKeyboard usable, focus visible, useful alt text
DocumentationREADME explains purpose, features, stack and learning
DeploymentPublic URL works with no broken assets

9. Curriculum alignment

This project expands Level 01 Module 5: project overview and Git setup, fonts and navigation, banner, about, skills, education/experience, contact form, GitHub hosting and icon use. Responsive/accessibility/documentation gates are marked as Saiful the Techie additions.
