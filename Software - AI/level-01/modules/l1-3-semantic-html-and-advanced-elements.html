1. Semantic HTML: choose elements for meaning

Semantic elements tell the browser, assistive technology and other developers what a region represents. They also make CSS and future component extraction easier.

2. A semantic page skeleton

HTML<header>...site identity...</header> <nav aria-label="Primary">...links...</nav> <main> <section aria-labelledby="featured-title"> <h2 id="featured-title">Featured projects</h2> <article>...one project...</article> </section> </main> <footer>...contact and legal...</footer>

Use div when there is no more meaningful element; it is not wrong, just neutral.

3. Audio, video and embedded media

HTML<video controls width="640" poster="poster.jpg"> <source src="demo.mp4" type="video/mp4"> Your browser does not support the video element. </video>

For third-party video embeds, use the provider's embed URL and give the iframe a descriptive title.

4. Better forms: fieldset, radio, checkbox and textarea

HTML<fieldset> <legend>Preferred contact method</legend> <label><input type="radio" name="contact" value="email"> Email</label> <label><input type="radio" name="contact" value="phone"> Phone</label> </fieldset> <label for="message">Message</label> <textarea id="message" name="message" rows="5"></textarea>

5. Tables are for data, not page layout

HTML<table> <caption>Course progress</caption> <thead><tr><th scope="col">Topic</th><th scope="col">Status</th></tr></thead> <tbody><tr><th scope="row">HTML</th><td>Complete</td></tr></tbody> </table>

6. Navigation between pages

Folderportfolio/ index.html projects.html contact.html css/ style.css
HTML<nav aria-label="Primary"> <a href="index.html">Home</a> <a href="projects.html">Projects</a> <a href="contact.html">Contact</a> </nav>

7. Flexbox bridge

Flexbox is ideal for arranging items along one main axis. You will go deeper in Module 4.

CSS.nav { display: flex; gap: 1rem; align-items: center; } .hero { display: flex; gap: 2rem; align-items: center; } .hero > * { flex: 1; }

8. Build a reusable card pattern

HTML<article class="card"> <h3>Analytics Dashboard</h3> <p>A short project description.</p> <a href="#">View project</a> </article>

10. Challenge

Build a three-page mini-site with shared navigation, one data table, one grouped form, one embedded video and semantic page regions. Do not use tables for layout.

11. Knowledge check

When should you use article?

For self-contained content that could stand on its own, such as a post, project card or news item.

Why use fieldset and legend?

To group related form controls and give the group an accessible label.

What is a table for?

Tabular data with meaningful row/column relationships, not general page layout.
