1. Project module: integrate the foundation

This module turns isolated HTML/CSS skills into one coherent portfolio. The source curriculum covers project setup, fonts, navigation, banner, about, skills, resume, contact form and GitHub hosting. Our expansion adds responsive, accessibility and documentation quality gates.

4. Build a small design system

CSS:root { --bg: #f7f8fc; --surface: #ffffff; --text: #171a26; --muted: #62687a; --brand: #5b37ff; --radius: 18px; --space: 1rem; }

Use a consistent type scale, spacing scale and a small set of colors rather than inventing values in every section.

5. Build in vertical slices

Navigation + hero

Make the opening screen readable on mobile before adding desktop layout.

About + skills

Use semantic sections and reusable cards.

Education + experience

Prioritize scanability over decorative complexity.

Projects

Every project card should explain the problem, solution, technologies and outcome.

Contact

Use labels and clear interaction states.

6. ST quality gates

Responsive

No horizontal overflow; content remains usable at narrow widths and zoom.

Accessible

Semantic structure, alt text, labels, visible focus, sufficient contrast.

Git history

Multiple meaningful commits, not one final dump.

Documentation

README with purpose, stack, features, live link and learning notes.

7. Publish with GitHub Pages

  1. Push the repository to GitHub.
  2. Open repository Settings → Pages.
  3. Choose the appropriate branch/source for your static site.
  4. Wait for deployment and test the public URL.
  5. Update README with the live URL.

9. Review questions

Why commit throughout the project?

It creates a meaningful history, makes debugging easier and demonstrates professional workflow.

What should a project card communicate?

The problem, your solution, technologies used and evidence/outcome.

Why test a portfolio with keyboard navigation?

To catch interaction problems that are invisible when testing only with a mouse.
