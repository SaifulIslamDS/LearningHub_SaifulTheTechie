Version Control with Git and GitHub

Learn Git as a working habit, not a list of commands: snapshot changes, write useful commits, push to GitHub, branch safely and recover from common mistakes.

1. Why version control matters

Git records the history of a project. GitHub hosts Git repositories and adds collaboration features such as pull requests, issues and code review. Learning both early gives every later project a professional workflow.

2. Mental model: working tree → staging area → repository

Working tree

Files you are editing now.

Staging area

The exact changes selected for the next commit.

Repository

Committed history on your computer.

GitHub is a remote home for that repository; it is not a replacement for Git.

3. One-time setup

Terminalgit --version git config --global user.name "Saiful Islam" git config --global user.email "you@example.com" git config --global --list

Use the email associated with your GitHub account if you want commits connected to your profile, or use GitHub's private noreply email.

4. Create your first local repository

Terminalmkdir profile-site cd profile-site git init git status git add index.html style.css git commit -m "Build initial profile page"
Commit principle: one commit should represent one understandable change.

5. Connect to GitHub and push

Create an empty repository on GitHub, then use the remote URL GitHub gives you.

Terminalgit branch -M main git remote add origin https://github.com/YOUR-USERNAME/profile-site.git git push -u origin main

After the first push, a normal update is often:

git status git add . git commit -m "Improve hero section" git push

6. Use .gitignore intentionally

Do not commit generated files, secrets or dependency folders that should be reproduced from configuration.

.gitignore.DS_Store .env node_modules/ dist/
Never commit secrets: API keys and passwords should not live in a public repository.

7. Branches and pull requests

Terminalgit switch -c feature/contact-section # edit files git add . git commit -m "Add contact section" git push -u origin feature/contact-section

On GitHub, open a pull request to compare the branch with main. Even when working alone, a pull request is useful practice for review-driven development.

8. Beginner recovery commands

See what changed

git status git diff

Unstage a file

git restore --staged file.html

Restore unstaged edits

git restore file.html

This discards local changes—check before running.

See history

git log --oneline --graph

9. Common issues

  • Push rejected: the remote has commits you do not have; fetch/pull and reconcile.
  • Wrong remote: inspect with git remote -v.
  • Wrong branch: inspect with git branch.
  • Authentication problem: follow current GitHub authentication guidance instead of using account passwords in Git.

11. AI-assisted workflow

AI can explain Git output, but paste only non-sensitive command output. Ask it to explain why a command is safe before running anything destructive.

12. Knowledge check

What is the staging area?

The selected snapshot of changes that will go into the next commit.

What is the difference between Git and GitHub?

Git is the version-control system; GitHub is a hosting/collaboration service for Git repositories.

Why create small commits?

They are easier to understand, review, debug and revert.

What does git push do?

Sends local commits to a configured remote repository.
