## 1. Why v0.9.1 exists

The dbt source lessons had been written, but the learner-facing `docs/` snapshot was older. A learner opening the packaged site could therefore see a future-status placeholder even though the source tutorial already existed. The generator also supported YouTube metadata but the M8 lessons did not consistently populate it, and there was no professional per-tutorial AI mentoring prompt in the actual product.

v0.9.1 is a **platform correction checkpoint** before more M8 content is added. It makes source state, roadmap state and learner-visible state agree.

## 3. Release-blocking anomalies found and fixed

### A. Source and generated site were out of sync — FIXED

**Problem:** written dbt Markdown existed, but the packaged `docs/` still showed the older learner-facing site.

**Fix:** the build now has an offline Pandoc renderer fallback when Python-Markdown is unavailable. `docs/` was regenerated from source.

**Current real build:** 199 pages · 10 phases · 93 modules · 85 lessons. `Internal links: all OK`.

This is now a release rule: a written source tutorial is not considered packaged successfully if the corresponding generated tutorial page is missing.

### B. Ambiguous future-status placeholder — FIXED

**Problem:** unwritten topics/modules used a generic future-status phrase that did not tell the learner when the material was scheduled.

**Fix:** generated pages now show the projected roadmap milestone/version. Examples:

- remaining Phase 3 material → **M8 · v0.9.x**
- Phase 5 / LLM & RAG → **M9 · v1.0**
- Phase 6 / Agents → **M10 · v1.1**
- Phase 4 / ML Engineering → **M11 · v1.2**
- Phase 7 / LLMOps & Governance → **M12 · v1.3**
- Phases 8–9 → **M13 · v1.4**

Unwritten curriculum rows are labelled **Planned curriculum topic**, not “planned lesson”, because one curriculum topic does not necessarily equal one tutorial page.

### C. No professional per-tutorial AI learning prompt — FIXED

Every written tutorial now receives an automatically generated, copyable **AI Mentor Prompt**.

The prompt is lesson-specific and includes:

- mentor role appropriate to the phase;
- current tutorial title and level;
- diagnostic question first;
- simple mental-model explanation;
- small hands-on task;
- wait-for-learner-attempt rule;
- code/work review;
- debugging before replacement;
- gradual difficulty increase;
- professional context;
- teach-back check;
- independent final task;
- current-official-documentation verification rule;
- no fabricated execution/output rule;
- linked practice-file guidance;
- relevant Phase 3 known-answer guardrails.

Generated result: **85 / 85 written tutorials contain the AI Mentor Prompt**.

### D. YouTube support existed but M8 lessons did not consistently use it — FIXED

The generator now renders a responsive privacy-enhanced YouTube frame plus:

- title;
- creator;
- duration when verified;
- level/language;
- reviewed date;
- explanation of why the video is relevant;
- useful timestamp links where appropriate;
- normal YouTube fallback link.

All **8 M8 tutorials completed so far** now have a reviewed companion:

- ETL/ELT: 2/2
- Data Quality: 3/3
- dbt: 3/3

The written tutorial remains complete without the video. Videos are not inserted merely to fill a frame.

### E. Old roadmap rules conflicted with the approved tutorial architecture — FIXED

**Problem:** an older section still required one lesson for every planned topic, exactly 3 quiz questions, a compulsory job-ready check, and a fixed 3–4 resource count.

**Why this was wrong:** it contradicted the approved deep-tutorial model and the rule that curriculum coverage does not control page count.

**Fix:** `ROADMAP.md` now says:

- every curriculum topic must be covered, but topics may be split/combined pedagogically;
- deep explanation and verified practical work drive tutorial structure;
- quiz/common-mistakes/summary/job-ready sections are optional;
- resources are curated for quality, not fixed quantity;
- every written tutorial gets the AI Mentor Prompt;
- YouTube is included only after review.

### F. Three completed Phase 1 modules lacked module introductions — FIXED

Added `_module.md` introductions for:

- Semantic Models & Metrics Layer
- AI-Assisted Analytics
- Data Storytelling

All modules that currently contain written tutorials now have a module introduction.

### G. Version semantics were becoming ambiguous — FIXED

M8 was originally described simply as `v0.9`. Once the owner approved a `v0.9.1` correction checkpoint before M8 completion, later calling the final M8 package `v0.9` would be a version downgrade.

The roadmap now treats M8 as the **v0.9.x release family**. Working/correction releases can advance through patch versions while all Phase 3B scope remains inside M8.

### H. Current continuation handovers were stale — FIXED

The v0.8-era handover now has an explicit current continuation notice. `M8-UPGRADE-CONTINUATION.md` is updated to:

- current checkpoint v0.9.1;
- dbt complete;
- AI-Ready Data next;
- current tutorial/prompt/video/build rules;
- current M8 order.

## 9. Improvements intentionally deferred

These are not v0.9.1 blockers:

- Older Phase 0–3A tutorials have not all been rewritten into long-form Template v2 prose. Their AI Mentor Prompt is present now; deeper prose/practice/video refresh should happen progressively rather than blocking M8.
- Older tutorials do not automatically receive random YouTube videos. A companion is added only after a relevant video is reviewed.
- Some older tutorials have fewer external resources than others. The current standard is relevance/quality, not an arbitrary fixed number.
- Full real-browser QA remains owner-side because this sandbox blocks browser navigation.
